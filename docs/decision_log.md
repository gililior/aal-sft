## Research question

Can a small reasoning model close the gap to classic automata learners (L*, TTT) on the agentic automata learning benchmark of Menaged et al. (arXiv:2606.16576), and does that transfer to other tasks?

- **Model:** Qwen3.5-4B, which thinks by default. Chosen over Gemini 3.8 Flash because Vertex's supervised tuning trains Gemini without its thinking, and Gemini 3.8 Flash isn't listed as tunable.
- **Approach, as of 2026-10-08:** RL with the oracle's verdict as the reward is now the main track. SFT on L*/TTT trajectories is kept as a comparison and as an RL starting point.
- **Gemini track:** built (visible `<THOUGHT>` format, Vertex tuning scripts) but not run. This workspace can't reach Google Cloud, so it would run from the cluster with your own login.
- **Code:** github.com/gililior/aal-sft (private), built on the paper's released code pinned at commit b8b93e2.

## Benchmark and evaluation

Evaluation reproduces the paper's setup exactly: same harness, same 160 instances, same budget, same counterexample rule.

| Choice | Value | Why |
| --- | --- | --- |
| Instances | 2–9 states × seeds 1–20 = 160, binary alphabet | Paper's benchmark; results reported in its buckets 2–3, 4–5, 6–7, 8–9 |
| Budget | 2× the better of L*/TTT per instance | Paper default |
| Counterexamples | Deterministic short | Paper default |
| Held-out data | Training seeds start at 100000 (SFT) / 1,000,000 (RL); any DFA equivalent to an eval target is dropped | No leakage into the benchmark |
| Metrics | Success rate (95% bootstrap CI), Δ tool calls on successes, invalid-turn rate | Paper's metrics plus a format check |
| Sampling | Temperature 0.6, top-p 0.95, top-k 20 | Qwen's thinking-mode setting for precise tasks; greedy decoding loops |

**Format check:** replaying the trajectories through the released `LLM_interactive_game` gives byte-identical messages, so the training data matches what the harness shows a model.

**Ceilings (teacher replay through the harness):**

| Teacher | 2–3 | 4–5 | 6–7 | 8–9 |
| --- | --- | --- | --- | --- |
| TTT | 100% (+1.9) | 100% (+0.7) | 100% (+1.0) | 100% (+0.8) |
| L* | 100% (+0.3) | 100% (+4.6) | 100% (+7.8) | 97.5% (+16.8) |

One instance (8 states, seed 1) needs 96 L* queries against a budget of 82, so a perfect L* imitator can't reach 100%.

**Open question:** in keep-reasoning mode the base model is evaluated with its earlier reasoning visible, unlike the paper's stateless scaffold. For a paper-faithful base number, also run the base eval with `TRAJ_MODE=per-turn`.

## Teacher data

There is one dataset per teacher (L* and TTT), each built from the same 2,110 training DFAs, 300 per size from 3 to 9 states plus the 10 two-state DFAs not in the eval set.

- **Teachers:** the paper's own L* (AALpy 2.0.0, Rivest–Schapire counterexample processing) and its "TTT". The latter is a discrimination-tree learner without TTT's discriminator finalization, so the TTT student imitates that implementation.
- **Reasoning traces:** generated by instrumenting the algorithms. At every oracle query the algorithm's real state is written out: the L* observation table and the cell being filled, or the TTT tree, access words and sift path, plus the counterexample analysis. These are exact, not written by an LLM.
- **Formats:** `think` (reasoning in the native thinking channel, for open models), `thought` (visible `<THOUGHT>` block, for Gemini), `stateless` (actions only, the paper's format), and `stateful` (the paper's four-block scaffold, rebuilt from its appendix).
- **Size:** L* 97k model turns, TTT 81k. Whole trajectories are 10–12k tokens at the median and up to ~42k; 21M (TTT) and 27M (L*) tokens per epoch.
- **Check:** each trajectory is replayed through the oracle, and every answer must match what the algorithm saw: 0 failures out of 4,220.

## SFT

The default supervises every model turn of a trajectory in one example, with earlier reasoning kept in context.

**SFT target, decided 2026-10-09:** actions plus algorithm state. L* and TTT only produce queries and hypotheses, so each turn's "reasoning" is the algorithm's internal state written out (observation table, discrimination tree, counterexample analysis), followed by the action. The model learns to make that state explicit before each move instead of inferring it silently, which is the skill the paper found missing.

| Choice | Value | Why |
| --- | --- | --- |
| Method | LoRA rank 32, alpha 64, lr 1e-4 cosine, 2 epochs, ~32k tokens per step | Fits one L40S; effective batch independent of GPU count |
| LoRA targets | Attention, MLP and Gated DeltaNet projections (`in_proj_qkv`, `in_proj_z`, `out_proj`) | Only 1 in 4 of Qwen3.5's token-mixing layers is standard attention |
| Trajectory mode | `full`: one example per trajectory, loss on every model turn | You want the whole trajectory supervised; also ~3× cheaper than per-turn splitting |
| Chat template | `templates/qwen_keep_reasoning.jinja`, used for training and serving | Qwen's template drops reasoning after each user message, and the oracle's answers arrive as user messages |
| Loss | Only the model's turns, never the prompt or oracle answers; computed in 2,048-row chunks with recomputation | Qwen3.5's ~250k vocabulary made full logits ~8 GB per example |
| Alternative | `per-turn` mode: one example per selected turn (all EQ turns + 8 MQ turns), earlier reasoning dropped | Matches Qwen's native format; used for the RL warm start |
| Adapters | Renamed to `model.language_model.*` after saving | Otherwise vLLM silently ignores them |

## RL

The main track, decided 2026-10-08: GRPO with the oracle's verdict as the reward, run from both the base model and an SFT model. Code pushed 2026-10-08 (`scripts/train_rl.py`, `scripts/slurm/rl.sbatch`); smoke-tested on the cluster 2026-10-09 (works end to end; rollouts are too slow for the full runs as configured, see Results).

| Choice | Decision | Why |
| --- | --- | --- |
| Start points | Both: base Qwen3.5-4B and the TTT per-turn SFT adapter, same budget | Shows what imitation adds before RL |
| Context | Qwen's native format: earlier reasoning dropped | Failed 9-state episodes run ~120 turns; keeping all reasoning means 100k+ tokens, too long to train on an L40S |
| SFT warm start | Per-turn mode (not full) | Must match the native format RL uses |
| Reward | Success only: 1 if the final equivalence query is correct, else 0 | Simplest and fully verifiable; no reward hacking possible |
| Credit | Every turn gets its episode's advantage (reward minus group mean) | Train on the whole trajectory, not just the final query |
| Groups | 8 DFAs × 8 episodes per step | Group-relative baseline; groups with all-equal rewards give no gradient |
| Curriculum | Start at ≤4 states; add a size when the hardest size passes 50% | Base model gets no reward on large DFAs |
| Setup | 4 L40S: 1 for vLLM rollouts, 3 for updates; adapter hot-reloaded each step | No CUDA compiler on the cluster; fewer moving parts than verl |

In the format choice, every earlier query and oracle answer stays visible to the model; only the old thinking text is dropped.

**Open question:** keep TTT as the RL warm start, or use L* (or both)?

## Infrastructure

Everything runs on the school Slurm cluster with L40S GPUs (45 GB), 24-hour jobs, no partition flag; H200s weren't available.

- **Layout:** environment at `/cs/snapless/gabis/gililior/virtual_envs/aal_sft`; HF, vLLM, Triton and pip caches under `/cs/snapless/gabis/gililior/`. The home quota filled during the first model download.
- **Jobs:** `prepare.sbatch` (environment, data, weights, GPU check), `smoke.sbatch`, `submit_all.sh`. Training uses 4 L40S, serving 1. Checkpoints ~20 times per epoch, and a resubmit resumes.

| Problem | Fix |
| --- | --- |
| `nvidia-smi` missing on compute nodes | Count GPUs from `CUDA_VISIBLE_DEVICES` |
| vLLM's FlashInfer sampler needs `nvcc` (not installed) | `VLLM_USE_FLASHINFER_SAMPLER=0` |
| transformers v5: `apply_chat_template` returns a dict | Shared `chat_ids()` helper; fail-fast if sequences look too short |
| transformers v5 removed `warmup_ratio` and `group_by_length` | `warmup_steps=0.03` |
| Out of memory on long examples (~8 GB logits) | Chunked loss on supervised positions only |
| RL smoke: output-projection weight left on CPU (taken before the model moved to GPU) | Take it after the move; same fix in SFT full-trajectory mode |

**Measured speed:** ~80 s per optimizer step on 1 L40S in the old per-turn setup, roughly 4.7 s per 8k-token example. Base-model inference ran ~270 tokens/s with 4 concurrent episodes.
